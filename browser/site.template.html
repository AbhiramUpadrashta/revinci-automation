End-to-end tests for your Revinci workspace

Admin setup, every product type, quote → order → entitlement, and the documented APIs, driven screen by screen. Run it right in your browser, or as a full app from Terminal.

tessla-workspace-dev.revinci.ai
Option A · nothing to install

Run it in your browser

Uses the Revinci login you already have. The test panel opens over Revinci with the screens on the left and results on the right.

  1. Open Revinci and log in, for example https://tessla-workspace-dev.revinci.ai/dashboard.
  2. Start the runner in that tab, either way:
    Bookmark: drag this button to your bookmarks bar (⌘ Shift B shows it), then click it on the Revinci tab.
    __LOGO__Revinci Tests
    Console: press ⌥ ⌘ J in the Revinci tab, paste this line and press Enter. If asked, type allow pasting first.
    __CONSOLE__
  3. Pick what to test (or Full end-to-end) and click Run tests. Download the report from the panel when it finishes.
Option B · Terminal on a Mac

Run the full app

A control panel at http://localhost:4600 where you enter the Revinci URL, email and password. A real Chrome window drives the screens. Needs Node.js 18+ and Git.

  1. First time: download and start 
    # download the app
git clone https://github.com/AbhiramUpadrashta/revinci-automation.git
cd revinci-automation

# install and start (opens http://localhost:4600)
npm install
npm start
  2. Next time: update and start. The first line closes any copy that is still running, so you never end up on an old version. 
    lsof -ti tcp:4600 | xargs kill -9 2>/dev/null
cd ~/revinci-automation
git pull
npm install
npm start
    Keep this Terminal window open while you use the panel. The panel title shows the build (for example build 2026-10-23.1); script updates you pull later take effect on the next run without restarting.
  3. Publish your changes to GitHub (repo owner only) 
    cd ~/revinci-automation
git add -A
git commit -m "Update automation flows"
git push
  4. Share it with your team (optional). Starts the app with a password and gives you a public trycloudflare.com link. It works while this Terminal stays open and the Mac is awake. 
    cd ~/revinci-automation
command -v cloudflared >/dev/null || brew install cloudflared
HOSTED=1 APP_PASSWORD='choose-a-password' npm start &
sleep 5 && cloudflared tunnel --url http://localhost:4600
    Copy the https://….trycloudflare.com address Cloudflare prints and share it with the password.

What it tests

Tick any mix. Each run tags its records with a code like ATK3F9Q, so runs never collide, and later steps reuse the account and product created earlier in the same run.

Admin setup

  • Currency and exchange rate
  • Unit of measure
  • Attribute and attribute group
  • Price profile and cost profile
  • Customer account

API key

  • Checks Settings ▸ API Keys
  • Reuses a saved key or one you paste
  • Creates one only if none is active
  • Shows the key in the panel

Product setup

  • Product, bundle, option, option group
  • Feature, feature offering, agent feature
  • Product with features or offerings
  • Simple agent: outcome + One Time, Subscription, Consumption (attribute based) and Margin prices
  • Workflow agent: Subscription $0, sub-agent with consumption matrix, outcome, offering

Quote · Order · Entitlement

  • Quote → bag → finalize → lifecycle
  • Account → order (first account typed in), first agent, LLM popup, finalize
  • Open the entitlement (eye icon) and activate with today’s date
  • Send a usage event to the plan

API testing

  • Auth checks, including bad keys
  • Accounts, entitlements, plans, rating
  • Wallets, carryover, consumption rules
  • Usage ingest, single and bulk

Good to know

  • Run it against the dev workspace. It creates real records there.
  • Option A never asks for a password; it works only in a tab where you're logged in. Option B asks for one per run and never saves it.
  • Revinci allows one active API key and shows its secret once. Paste your existing key into the panel, or tick Revoke & recreate to replace it.
  • If a step fails, the report shows the screen it stopped on, and the Failed APIs tab shows the request and response.
  • The new agent flows run only in the full app (Option B); the in-tab runner (Option A) covers the other suites.
